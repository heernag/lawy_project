# 최종 코드리뷰 노트

작성일: 2026-07-15

이 문서는 무료 버전 백엔드 MVP의 최종 코드리뷰 요약입니다.

## 전체 결론

현재 백엔드는 무료 MVP 기준으로 거의 완료 상태입니다.

확인된 상태:

- 유료 LLM API 사용 없음
- 유료 임베딩 API 사용 없음
- 유료 벡터 DB 사용 없음
- 유료 판결문 API 사용 없음
- 무단 크롤링 없음
- 저장된 샘플 판결문만 검색/조회
- 공통 API 응답 형식 사용
- Swagger/OpenAPI 제공
- 프론트 연동 문서와 Bruno 컬렉션 제공
- 주요 기능 테스트 통과

최근 검증:

```text
python -m pytest -q
94 passed, 1 warning
```

경고 1개는 기존 FastAPI/Starlette TestClient 관련 경고입니다.

## 잘 된 점

### 1. 구조 분리

API 라우트, 서비스 로직, 데이터 공급자, DB 저장소, 스키마, 문서가 분리되어 있습니다.

좋은 점:

- 한 파일에 모든 기능을 넣지 않았습니다.
- 나중에 공식 공공데이터 provider를 붙일 수 있는 구조입니다.
- 프론트 연동 문서와 API 코드가 같은 방향을 보고 있습니다.

주의할 점:

- 앞으로도 라우트 파일에 DB 접근이나 AI 로직을 직접 넣지 않는 것이 좋습니다.

### 2. 무료 버전 원칙

현재 구현은 전부 로컬/무료 기반입니다.

사용 중:

- SQLite
- 샘플 판결문 JSON
- 로컬 규칙 기반 사건 분석
- 로컬 키워드 검색
- 무료 로컬 해시 임베딩
- 로컬 검증 로직

사용하지 않음:

- 유료 AI API
- 유료 임베딩 API
- 유료 벡터 DB
- 유료 판결문 API

주의할 점:

- 실제 공식 판결문 데이터를 붙이기 전에는 저장, 재배포, 원문 표시, 상업적 이용 조건을 다시 확인해야 합니다.

### 3. 검색과 조회

구현된 기능:

- 사건번호 정확 검색
- 키워드 검색
- 날짜 필터
- 분야/법원/결과 필터 구조
- 로컬 유사도 검색
- 판결문 상세 조회
- 유사 판결문 조회

좋은 점:

- 존재하지 않는 판결문을 만들어내지 않습니다.
- 검색 결과는 저장된 데이터에서만 나옵니다.
- `similarity_score`는 승소 가능성이 아니라 검색 관련도입니다.

주의할 점:

- 로컬 해시 임베딩은 MVP용 유사도 보조 기능입니다. 법률 의미를 깊게 이해하는 모델은 아닙니다.

### 4. 문단 분리

구현된 섹션 인식:

- 주문
- 청구 취지
- 이유
- 인정 사실
- 원고 주장
- 피고 주장
- 법원의 판단
- 결론
- 관련 법령
- 항소취지
- 항소이유
- 상고이유
- 범죄사실
- 증거의 요지
- 법령의 적용
- 양형의 이유
- 처분의 경위
- 관계 법령
- 판단

좋은 점:

- 문단 ID가 안정적으로 만들어집니다.
- 특정 문단만 다시 쉬운 설명으로 변환할 수 있습니다.
- 형사/행정 판결문 제목 fixture가 추가되었습니다.

주의할 점:

- 실제 판결문 형식은 더 다양하므로 새 형식은 fixture 테스트를 먼저 추가한 뒤 확장해야 합니다.

### 5. 쉬운 설명과 검증

검증 항목:

- 금액
- 날짜
- 사건번호
- 이자율/비율
- 법률 조항 번호
- 원고/피고 역할
- 지급 의무 주체
- 기각/인용 등 결과 표현
- 부정 표현
- 원문에 없는 사실 추가

좋은 점:

- 검증 실패 시 `review_required` 상태를 반환할 수 있습니다.
- 쉬운 설명을 원문 문단과 연결합니다.
- 원문과 다른 내용을 정확한 설명처럼 보여주지 않도록 설계되어 있습니다.

주의할 점:

- 현재 쉬운 설명은 규칙 기반 MVP입니다. 법률적으로 완전한 번역 엔진은 아닙니다.

### 6. 개인정보와 입력 안전

구현된 내용:

- 전화번호 마스킹
- 주민등록번호 형식 마스킹
- 이메일 마스킹
- 명확한 도로명 주소 마스킹
- 금액 표현 주소 오탐 방지
- 순번 표현 주소 오탐 방지
- 프롬프트 인젝션 의심 문구 경고

좋은 점:

- 사용자 입력을 무조건 장기 저장하지 않는 방향입니다.
- 프론트에서 `sanitized_query`를 보여줄 수 있습니다.

주의할 점:

- 주소 탐지는 보수적입니다. 모든 주소를 잡지는 못합니다.

### 7. 프론트 연동

제공된 자료:

- Swagger
- OpenAPI JSON
- API 문서
- 프론트 화면 흐름 가이드
- TypeScript 타입 예시
- Bruno 테스트 컬렉션
- `.env.example`
- README 실행 가이드

좋은 점:

- TypeScript 타입 예시가 실제 `snake_case` 응답과 맞습니다.
- OpenAPI 핵심 경로와 공통 응답 스키마를 테스트로 확인합니다.
- 모든 핵심 공개 경로의 200 응답과 주요 400/404 오류 응답이 공통 `ApiResponse` 스키마로 문서화됩니다.
- `SIMILARITY_MODE=local_hash`는 실제 검색 서비스에서 검증됩니다. 지원하지 않는 모드는 오류로 막습니다.
- 에러 처리는 `error.code` 기준으로 하도록 문서화했습니다.

주의할 점:

- TypeScript 타입은 아직 수동 문서입니다. 나중에 프론트가 원하면 OpenAPI 기반 자동 생성으로 바꿀 수 있습니다.

## 남은 리스크

필수 기능 리스크는 크지 않습니다.

남은 리스크:

- 완전히 새 컴퓨터에서 의존성 설치부터 재검증하지는 않았습니다.
- 실제 공식 판결문 provider는 아직 구현하지 않았습니다.
- 실제 공개 판결문 형식 fixture는 더 늘릴 수 있습니다.
- Alembic 운영 마이그레이션은 MVP 이후 정리 대상입니다.

## 최종 판단

무료 백엔드 MVP 기준으로는 프론트 인계 가능한 상태에 매우 가깝습니다.

운영/상용 수준으로 가기 전에는 다음이 필요합니다.

- 공식 데이터 출처 약관 확인
- 실제 공개 판결문 샘플 확대
- 운영 DB 마이그레이션 정리
- 더 강한 무료 검색 모델 검토
- 법률 전문가 리뷰

현재 단계에서는 큰 기능 개발보다 최종 검증과 인계 문서 정리가 중심입니다.
